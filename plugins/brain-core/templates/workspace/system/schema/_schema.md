# Knowledge-base schema v3

Markdown is the source of truth. `system/kb.db` is generated by `brain kb build`, git-ignored and
rebuildable at any time. This file, `kb.sql` and `entry-grammar.md` are the contract for the
`brain kb` commands and for any viewer built on top. `attention.yaml` is yours to tune.

## 1. Entity types

| Entity | Home | ID | Notes |
|---|---|---|---|
| project | `projects/<slug>/` | `proj-<slug>` | facet logs, `teams.md`, `decisions/`, `rollups/`, `artefacts/` |
| person | `people/<person-id>.md` + `people/_org.yaml` | `<first>-<last>` | same ID in the org chart and the page |
| topic | `topics/<slug>/` | `topic-<slug>` | page + logs, like a project without a team |
| raw item | `raw/<kind>/YYYY/YYYY-Www/` | `<kind>-YYYY-MM-DD-<slug>` | immutable source material |
| digest | `digests/{weekly,monthly}/` | `dig-<period>` | generated rollup |
| proposal | `inbox/proposals/PRP-NNN-<slug>.md` | `PRP-NNN` | system or owner improvement; never auto-applied |
| system ADR | `system/adrs/` | `ADR-NNN` | decisions about the system itself |
| code repo | `code/<repo>/README.md` | `repo-<name>` | card only; the repo has its own git |

## 2. IDs

- **Raw items:** filename stem = ID = `<kind>-YYYY-MM-DD-<slug>`. Kinds by folder: `raw/meetings` → `mtg`,
  `raw/slack` → `slack`, `raw/confluence` → `conf`, `raw/notes` → `note`, `raw/sources` → `src`.
  The slug is kebab-case from the title (for Slack, the channel). Cite as `[[id]]`.
- **Facet entries:** numbered per project and prefix, never reused: `RSK-NNN`, `DEP-NNN`, `MS-NNN`,
  `STA-NNN`, `RES-NNN`, `HYP-NNN`. The global key is `<project-slug>/<ID>`.
- **Decisions:** one file each, `projects/<slug>/decisions/YYYY-MM-DD-<slug>.md`, ID `DEC-<slug>-NNN` in frontmatter.

## 3. Entry grammar (summary; full spec in `entry-grammar.md`)

```markdown
## 2026-10-30 · RSK-014 · open
by: ai · trust: high · source: mtg-2026-10-30-partner-sync · owner: sam-patel · due: 2026-11-15
Partner sandbox contract slips past the freeze; blocks MS-006.
```

A header line, one metadata line, then a free body. Logs are append-only: a change is a new entry
with the same ID, and the latest dated entry is the current state.

## 4. Provenance

`by:` is mandatory on every entry and decision.
- `human`: written or edited by the owner. `ai`: written by an agent. `ai-confirmed`: AI-written, then confirmed by the owner with `brain kb confirm`.
- AI-written decisions start `status: proposed`. Only HIGH-trust sources may auto-confirm, and never when the text hedges ("proposed", "not final", "recommendation").
- `<!-- human -->…<!-- /human -->` fences mark text agents never rewrite.
- `source:` is mandatory (raw ID, another entry ID, or `owner`). Check: `select count(*) from entries where source is null` returns 0.

## 5. Trust tier (computed, never typed by hand)

Per raw item and per project, from `people/_org.yaml`, `projects/<slug>/teams.md` and the item's `attendance:` map:
- **HIGH**: the workspace owner (`owner.person_id` in `.claude/brain.json`), the project owner or a project decision-maker attended; or the owner's own note.
- **MEDIUM**: a project team member attended; Slack and Confluence items are MEDIUM.
- **LOW**: otherwise.

`attendance:` values are `attended | invited-absent | not-invited`. Only `attended` counts.
Only HIGH can auto-confirm; MEDIUM and LOW land as `proposed`.

## 6. Raw rules

`raw/<kind>/YYYY/YYYY-Www/` (ISO week, two-digit week, capital W). Immutable. A raw item is a
markdown file with frontmatter (`<id>.md`), optionally with a `<id>.summary.md` beside it (a
meeting summary) and a `<id>.meta.yaml` sidecar for items whose source can't carry frontmatter
(a `.txt` transcript). Frontmatter keys the index reads: `id, title, date, project, meeting_type,
attendance, sensitivity, redact_content, wiki_processed`.

## 7. Rollups

Meeting summary → weekly digest → monthly rollup per project (`projects/<slug>/rollups/YYYY-MM.md`).
Full-text search answers exact lookups; raw is opened only to verify.

## 8. Generated files

Every content folder gets a generated `_index.md` (`brain kb index`). Each project README starts
with a generated current-state block between `<!-- generated -->` markers; the rest is the
owner's narrative.

## 9. Contract

`brain kb`: `build, index, query, show <id>, attention, trust, append, propose, confirm`. `query`
prints JSON lines. A breaking change needs a new schema major version.
